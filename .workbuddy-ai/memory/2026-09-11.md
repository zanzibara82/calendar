## Реализован CalDAV-клиент синхронизации Яндекса (доделали)
Пользователь подтвердил: «давай доделаем синхронизацию CalDAV-клиент».
- Новые файлы (без новых зависимостей — переиспользуем `OkHttpClient`,
  `XmlPullParser`, `Base64` из Android SDK):
  - `data/remote/yandex/IcsMapper.kt` — Event↔VCALENDAR (RFC 5545). Поля:
    UID, DTSTART/DTEND (UTC Z), SUMMARY/DESCRIPTION (escape `\, \; \\ \n`),
    RRULE (только FREQ=), VALARM/TRIGGER (напоминания), LAST-MODIFIED.
  - `data/remote/yandex/CalDavClient.kt` — транспорт: host `https://caldav.yandex.ru`
    (НЕ `caldav.imap.yandex.ru`), HTTP Basic (`user=email, pass=OAuth-token`),
    PROPFIND-цепочка discover (`current-user-principal`→`calendar-home-set`→
    список календарей), REPORT calendar-query (pull), PUT/DELETE `<cal>/<uid>.ics`.
    Парсинг multistatus (HTTP 207) через `XmlPullParser`.
  - `data/remote/yandex/YandexCalendarDataSource.kt` — переписан из заглушки в
    реальный `RemoteCalendarDataSource`; `hasReliableUpdatedAt=false` (у Яндекса
    нет колонки «время изменения» → SyncRepository сверяет события по содержимому).
- `SettingsViewModel.syncAvailable` для YANDEX теперь `true`; в `SettingsScreen`
  убран блок «синхронизация недоступна». Кнопка «Синхронизировать» активна.
- Тесты `IcsMapperTest` (JUnit4, JVM): 5 тестов. Поймал и починил 3 бага:
  1. `unescape` — `\\N` как regex давал `PatternSyntaxException` (в Java `\N`
     невалиден). Заменено на однопроходный `\\(.)` с when по группе.
  2. Тест-ассерт строки спецсимволов: `\\n`→`\\\\n` (в description `\\n` —
     это literal backslash + 'n', экранируется в 3 символа).
  3. **Реальный баг синхронизации**: `fromIcs` мапил КАЖДУЮ строку `DESCRIPTION:`
     (в т.ч. внутри VALARM, где DESCRIPTION=title) в описание события →
     описание перезаписывалось заголовком. Добавлен гард `if (!inAlarm)` на
     UID/SUMMARY/DESCRIPTION/DTSTART/DTEND/RRULE/LAST-MODIFIED.
- Unit-тесты зелёные; `assembleRelease` успешен (R8 full mode, значит Hilt-граф
  с новыми классами валиден). `app-release.apk` = 2 487 243 B.

## Интеграционный тест CalDAV + ещё один реальный баг
Добил проверку транспорта без токена пользователя — локальным mock-сервером.
- `CalDavClientIntegrationTest.kt` (JVM, `app/src/test`): мини-HTTP-сервер на чистом
  `java.base` (`ServerSocket`, свой `indexOfSequence` для CRLFCRLF) вместо
  `com.sun.net.httpserver` (вне default-класспаса тестов AGP → Unresolved reference).
  XML-парсер `org.xmlpull.v1` на JVM-тестах добавлен через `testImplementation
  "net.sf.kxml:kxml2:2.3.0"` (он уже в gradle-кэше; в APK не попадает — только тесты).
  Тесты: (1) discover→fetch→put/delete против имитации `caldav.yandex.ru` с абсолютными
  href, проверяет выбор календаря «Календарь», Basic-auth, пути `<url>/<uid>.ics`;
  (2) 401 → понятная `CalDavException` про токен.
- **Реальный баг пойман тестом**: `fetchEvents` слал `calendar-query` методом
  `PROPFIND`, а по RFC 4791 `calendar-query` — это `REPORT`. Яндекс бы его отверг.
  Добавил `CalDavClient.report(...)` (method REPORT) и переключил `fetchEvents` на него.
- `CalDavClient` переведён с `android.util.Base64` на `java.util.Base64`
  (`getEncoder().encodeToString`) — чище, JVM-тестабельно, на API 26+ доступно.
  `baseUrl` вынесен в конструктор (`= "https://caldav.yandex.ru"`) для тестов.
- `testDebugUnitTest assembleRelease` — BUILD SUCCESSFUL (все JVM-тесты зелёные,
  R8 full mode прошёл). Повторный smoke-тест на эмуляторе: ставится, стартует,
  процесс жив, без FATAL/Dagger. `app-release.apk` пересобран с правками.
- Все 3 слоя проверки теперь есть: ICS-сериализация (IcsMapperTest), транспорт
  CalDAV (CalDavClientIntegrationTest), сборка+запуск (emulator smoke).
