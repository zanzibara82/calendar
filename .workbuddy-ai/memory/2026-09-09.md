# 2026-09-09 — MyCalendar

## 1. Починка SystemCalendarTest (причина падения на API 28)
`event_withVoiceAndTextNote_roundTrip` падал с
`IllegalStateException: Нет доступа к календарю телефона`, хотя второй тест в том же
процессе проходил. Причина: `uiAutomation.executeShellCommand("pm grant …")` —
**асинхронный**, разрешение не успевало примениться к старту первого теста класса.

Решение: заменить shell-выдачу на синхронный `GrantPermissionRule`
(внутри использует `UiAutomation.grantRuntimePermission`, доступен с API 28):

```kotlin
@get:Rule(order = 0)
val permissionRule: GrantPermissionRule = GrantPermissionRule.grant(
    Manifest.permission.READ_CALENDAR, Manifest.permission.WRITE_CALENDAR)
@get:Rule(order = 1)
val hiltRule = HiltAndroidRule(this)
```

Тот же асинхронный `pm grant` остался в AppUiTest / SchedulerAndMediaTest /
EndToEndReminderTest, но только для `POST_NOTIFICATIONS` на API 33+ — пока не мешает.

## 2. SystemCalendarTest на чистом AVD без календарей
На Android 11 (AVD `Api30`, `system-images;android-30;google_apis;x86_64`) в
CalendarProvider нет ни одного календаря → `resolveAndPersist` кидает
«На телефоне нет календарей, доступных для записи».

Тест сделан самодостаточным: в `@Before`, если `dataSource.writableCalendars()`
пуст, создаётся локальный календарь (ACCOUNT_TYPE = `CalendarContract.ACCOUNT_TYPE_LOCAL`,
ACCESS_LEVEL = OWNER, URI с `CALLER_IS_SYNCADAPTER=true`); в отдельном `@After`
календарь удаляется. Если создать не удалось — `Assume.assumeTrue(...)`, тест
скипается, а не падает.

## 4. Baseline Profile: что удалось выяснить
- AVD `BP_34` (API 34) на этой машине **не поднимается**: adb висит в `offline`
  15 минут, потом процесс умирает (16 ГБ ОЗУ, Android Studio съедает ~2 ГБ).
  API 30 и 28 грузятся за 45–60 с, API 34 — нет. Попытки: `-no-window`,
  RAM 2048→1536, cores 4→2 — не помогли.
- `:app:generateBaselineProfile` / `generateNonMinifiedReleaseBaselineProfile`
  **не создаются**: AGP здесь 9.4.0, плагин `androidx.baselineprofile` 1.4.1
  не подхватывается как consumer. В модуле `:baselineprofile` таск
  `collectNonMinifiedReleaseBaselineProfile` есть.
- **Важное наблюдение**: release-APK УЖЕ содержит `assets/dexopt/baseline.prof`
  (8236 B) и `baseline.profm` — AGP сам мержит baseline-профили зависимостей
  (androidx/Compose). Плюс подключён `androidx.profileinstaller`, так что
  профиль применяется при установке. Свой app-специфичный профиль нужен
  для ускорения собственного кода — его генерация отложена до машины/устройства
  с API 33+.

## 7. Yandex CalDAV: тест оркестрации `YandexCalendarDataSource` + DI-швы
Была непокрытая юнит-тестами прослойка — `YandexCalendarDataSource` (связывает
`IcsMapper` + `CalDavClient`: генерация UID, `credentials()`, discovery→fetch/put/delete).
Добавлен `YandexCalendarDataSourceTest` (4 теста, JVM): insert генерит UUID и шлёт
PUT `<календарь>/<uid>.ics` с VEVENT; fetchUpdatedSince прогоняет discovery+REPORT и
отдаёт распарсенный `RemoteEvent`; `credentials()` кидает `YandexCalendarUnavailableException`
при null-токене и при null-email аккаунта.

Ради тестабельности на JVM (без Android Keystore) сделаны два рефакторинга DI:
- выделен `interface AccessTokenProvider { fun getAccessToken(): String? }` (в `data/auth`),
  `YandexAuthDataSource` его реализует; `YandexCalendarDataSource` зависит от интерфейса,
  а не от конкретного класса (dependency inversion, как уже у `AuthRepository`).
- `YandexCalendarDataSource` теперь получает `CalDavClient` (инжектится), а не строит
  `CalDavClient(http)` с захардкоженным `https://caldav.yandex.ru` — тест передаёт
  клиент с mock-URL.

**Важные уроки Hilt/Dagger (поймали на компиляции):**
1. Hilt НЕ биндит класс с `@Inject`-конструктором к его интерфейсу-супертипу
   автоматически — нужен явный `@Binds` (`RepositoryModule.bindAccessTokenProvider`).
2. Dagger НЕ учитывает Kotlin default-значения параметров `@Inject`-конструктора —
   `String baseUrl = "..."` вызвало `MissingBinding String`. Решение: убрать `@Inject`
   у `CalDavClient` и дать `@Provides` в `NetworkModule` (дефолтный URL), тесты
   конструируют `CalDavClient(http, baseUrl=mock)` напрямую.

Test-infra: вынесен общий `MiniCalDavServer` (ServerSocket, java.base) + `yandexMockServer`
и mock-XML (`principalXml/homeSetXml/calendarsXml/eventsXml`) в
`app/src/test/.../remote/yandex/MiniCalDavServer.kt`; `CalDavClientIntegrationTest`
переписан на него (без дублирования).

Результат: `assembleDebug` зелёный (Hilt-граф валиден), 11 JVM-тестов зелёных
(YandexCalendarDataSourceTest 4 + CalDavClientIntegrationTest 2 + IcsMapperTest 5).
