## Фон экрана входа (4 картинки, случайный)

Задача: 4 иллюстрации календаря сделать фоном экрана с кнопкой «Войти»,
случайная — одна из четырёх.

- Исходники: `C:\Users\obogr\Downloads\calendar_4_variants\*.png`, 512×768.
- Пережаты в WebP q82 через Pillow (venv
  `~/.workbuddy-ai/binaries/python/envs/default`) → 30–32 КБ каждая
  (1.44 МБ → 126 КБ). Положены в `res/drawable-nodpi`:
  `auth_bg_plans`, `auth_bg_features`, `auth_bg_day_planning`,
  `auth_bg_all_in_one`.
- `presentation/auth/AuthScreen.kt`: `Box` → `Image(painterResource,
  ContentScale.Crop, fillMaxSize)` + `Box.background(scrimBrush)` + `Scaffold
  (containerColor = Color.Transparent)`.
- Scrim — вертикальный градиент цветом `colorScheme.surface`, плотность
  зависит от темы (яркость surface считается вручную по sRGB-весам):
  светлая тема `0.30/0.45/0.55`, тёмная `0.68/0.74/0.82`.
  Все 4 картинки светлые (среднее 210–240), поэтому в тёмной теме без
  плотного scrim текст не читался бы.

### Грабли
- `rememberSaveable` для random → НЕ годится: сохранённое состояние
  переживает смерть процесса, один фон «залипал» на многие запуски.
  Проверено: 5 force-stop подряд давали 1–2 варианта. `remember` — ок.
- Проверка «виден ли фон» без глаз: `screencap` + Pillow `ImageStat` по
  полосам. stddev ≈ 0 → картинки нет (сплэш/пустой surface); stddev 20–45 →
  фон виден. Первый вариант scrim (0.62/0.72/0.84) давал stddev ~22
  («замылен»), адаптивный — ~42.
- Тёмную тему включать: `adb shell cmd uimode night yes` (работает на API 28);
  назад — `night no`.
- Кнопка настроек в TopAppBar не попадает в `uiautomator dump`; искали её
  по тёмным столбцам пикселей в полосе y 90–200 → иконки на x 857–903
  (Today) и 983–1029 (Settings) при 1080×2400.

## Яндекс.Календарь: scope `calendar:all`

Пользователь скинул страницу согласия Яндекса с 12 правами «Яндекс.Календарь».
Раньше в `SCOPES` были только `login:info login:email` (Паспорт).
Для Календаря нужен отдельный scope: **`calendar:all`** (используется
yax CLI, caldav-cli, ical4j-клиентами).

- `YandexAuthDataSource.SCOPES = "login:info login:email calendar:all"`.
- В KDoc: scope покажет 12 прав на экране согласия; CalDAV-клиента в проекте
  пока нет — scope запрошен заранее, чтобы токен был пригоден без
  переавторизации.
- В KDoc `OAuthConfig` дописано: в карточке приложения на oauth.yandex.ru
  нужно включить «Яндекс.Календарь» в разделе «Доступы».
- CalDAV-сервер Яндекса: `caldav.yandex.ru` (не `caldav.imap.yandex.ru`).

Проверено: в логкате OAuth URL содержит
`scope=login%3Ainfo+login%3Aemail+calendar%3Aall`.

## «Убрать иллюзию» — честный UI + персистенция токена

Выбранный пользователем вариант из развилки: «Оставить вход, убрать иллюзию».
Сделано:

1. **`CalendarConnectionState.syncAvailable: Boolean`** (SettingsViewModel.kt):
   - `GOOGLE → true`, `YANDEX → false`, `LOCAL → true`.
   - Для Яндекса `false` — пока нет CalDAV-клиента, реальная синхронизация
     не работает.

2. **Карточка в SettingsScreen.kt**: при `!syncAvailable` показываем
   предупреждение цветом `tertiary` («Вход выполнен, но синхронизация с
   Яндекс.Календарём пока не реализована (требуется CalDAV-клиент)»).
   Кнопка «Синхронизировать» блокируется `enabled = !busy && syncAvailable` —
   пользователь не натыкается на CalDAV-ошибку.

3. **Персистенция токена** (YandexAuthDataSource.kt):
   - Добавлен `androidx.security:security-crypto:1.1.0-alpha06` в
     `libs.versions.toml` + `app/build.gradle.kts`.
   - `EncryptedSharedPreferences` (`AES256_GCM` для значений) + мастер-ключ
     `AES256_GCM` в Android Keystore. Файл: `yandex_oauth_secure.xml`.
   - В `init { }` токен поднимается из хранилища — переживает смерть процесса.
   - В `onRedirect` при получении нового токена — пишем в prefs.
   - В `reset()` (выход) — чистим prefs.

4. **R8**: `security-crypto` тянет Tink, у которого зависимости на Error Prone
   аннотации (`com.google.errorprone.annotations.*`). R8 ругается — добавил
   `-dontwarn com.google.errorprone.annotations.**` в `proguard-rules.pro`.
