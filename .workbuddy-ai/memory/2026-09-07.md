# 2026-09-07 — MyCalendar

## Концепт: вход в приложение ≠ синхронизация календарей

Пользователь уточнил концепцию: вход через Яндекс/Google как способ «войти в приложение»
не нужен. Нужна только **синхронизация календарей** этих провайдеров.

- С главного экрана убраны кнопки Google/Яндекс — осталась только кнопка **«Войти»**.
- В **Настройках** появилась секция «Календари» с двумя независимыми карточками
  (Google Календарь / Яндекс Календарь) — у каждой иконка («G» / «Я»), статус
  «Не подключён» и кнопки «Подключить» / «Отключить» / синхронизация.
- Провайдеры подключаются и синхронизируются **независимо** (можно оба сразу).

## Архитектура (миграция с «одного аккаунта» на «несколько провайдеров»)

- `SettingsRepository`: добавлены `onboardingCompleted` (флаг входа в приложение,
  отдельно от наличия аккаунта), `lastSyncTime(provider)` / `setLastSyncTime(provider, …)`.
  `setOnboardingCompleted()` → `setOnboardingCompleted(completed: Boolean = true)`
  (нужно было для сброса флага в UI-тестах).
- `AuthRepository`: вместо `currentUser` — `connections: Flow<List<CalendarConnection>>`,
  `accountFor(provider)`, `connectedProviders()`, `signInWithGoogle`, `signInWithYandex`,
  `signOut(provider)`, `signOutAll()`, `getAccessToken(provider, forceRefresh)`.
- `AuthRepositoryImpl`: ключи DataStore **на провайдер** (`account_google_email`,
  `account_yandex_email`), legacy-ключи читаются как fallback.
- `SyncRepository`: `syncNow()` (все подключённые) + `syncProvider(provider)`;
  `SyncResult` получил поле `provider`.
- Push: события с `calendarProvider == LOCAL` отправляются **только если подключён ровно
  один провайдер** (иначе событие дублировалось бы в оба облака).
- `EventDao.attachToProfile` → `attachToProvider(id, remoteId, provider)` — привязка
  созданного в облаке события к провайдеру одним UPDATE.
- `SplashViewModel` теперь решает destination по `settingsRepository.onboardingCompleted`,
  а не по наличию аккаунта.

## Исправления UI-тестов (важно, легко повторить)

1. **`HiltAndroidRule` НЕ инжектит поля теста автоматически** — нужно явно вызвать
   `hiltRule.inject()` в `@Before` (`setUp`). Без этого `@Inject lateinit` поля остаются
   неинициализированными. Признак: `UninitializedPropertyAccessException` в теле теста.
   Ловушка: если обращение к полю обёрнуто в `runCatching`, ошибка молча глотается.
2. **`assertExists()` требует ровно одну ноду.** Текст «Подключить» встречается дважды
   (по карточке на каждый провайдер) → использовать
   `onAllNodesWithText(...).assertCountEquals(2)`.
3. Тесты падали из-за переиспользования Activity + общего DataStore: после клика «Войти»
   в одном тесте флаг `onboardingCompleted` оставался `true`, и Splash пропускал экран
   входа в следующем тесте. Решение: сбрасывать флаг в `@Before`
   (`settingsRepository.setOnboardingCompleted(false)`).
4. «Process crashed» в конце прогона — **не** падение кода, а смерть эмулятора.
   Перезапуск эмулятора → прогон зелёный.

## Вечер: переход Google на CalendarContract, скрытие Яндекса

### Решения
- Google → `CalendarContract` (system calendar). OAuth-клиент/Google Cloud Console
  не нужны: аккаунт уже синхронизируется системой.
- Яндекс → карточка скрыта, пока `OAuthConfig.YANDEX_CLIENT_ID` пуст.

### Что появилось
- `data/system/SystemCalendarDataSource.kt` — реализация `RemoteCalendarDataSource`
  через `CalendarContract.Calendars` / `Events` / `Reminders`. Выбор календаря
  сохраняется в DataStore (`system_calendar_id`/`account`). `hasReliableUpdatedAt = false`.
- `RemoteCalendarDataSource.hasReliableUpdatedAt` (новое свойство интерфейса, default true).
- `SyncRepositoryImpl.doSync` — content-based разрешение конфликтов для
  провайдеров без `updatedAt` (см. `sameContent`); корректно обрабатывает
  `Events.DELETED=1`.
- `AuthRepository.connectGoogleCalendar()` + новый `MANAGED` без YANDEX, пока
  client_id не задан.
- `SettingsViewModel`/`SettingsScreen` — кнопка «Подключить» Google теперь запрашивает
  `READ/WRITE_CALENDAR` через `RequestMultiplePermissions`; убран AccountPicker
  и consent-диалог.
