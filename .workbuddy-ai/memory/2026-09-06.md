## Bugfix: напоминания не звучали на Android 9 при активном экране

**Проблема:** На Android 9 (API 28) звук напоминания не воспроизводился и окно не появлялось,
когда экран был активен. Full-screen intent в NotificationCompat подавляется системой при активном экране.

**Решение:** В `AlarmReceiver.onReceive()` добавлен прямой запуск `ReminderActivity` через
`context.startActivity()` с `FLAG_ACTIVITY_NEW_TASK`, в дополнение к показу уведомления.
Используется `PowerManager.WakeLock` (SCREEN_BRIGHT_WAKE_LOCK + ACQUIRE_CAUSES_WAKEUP)
для гарантии, что экран включится и CPU не уснёт до запуска activity.

**Изменённые файлы:**
- `app/src/main/java/com/example/mycalendar/notifications/AlarmReceiver.kt` — прямой запуск ReminderActivity + WakeLock
- `app/src/main/java/com/example/mycalendar/notifications/NotificationHelper.kt` — добавлен метод `buildReminderLabel()` для переиспользования текста напоминания
- `app/src/main/java/com/example/mycalendar/notifications/ReminderActivity.kt` — добавлен try/catch вместо runCatching, логирование MediaPlayer
- `app/src/main/java/com/example/mycalendar/work/ReminderScheduler.kt` — добавлено диагностическое логирование
- `app/src/androidTest/java/com/example/mycalendar/EndToEndReminderTest.kt` — новый e2e тест

**Тестирование:** Тест `SchedulerAndMediaTest.alarmChain_firesAndPostsNotification` проходит
как при активном, так и при выключенном экране на эмуляторе Android 9 (API 28).
MediaPlayer успешно создаётся (duration=2403 ms), ReminderActivity проходит полный lifecycle.

## Аутентификация: Google + Яндекс

**Диагноз (подтверждён instrumented-тестом `AuthDiagnosticTest`):**
- Яндекс HTTP 400 — `YandexAuthDataSource.CLIENT_ID` был плейсхолдером
  `"REPLACE_WITH_YANDEX_CLIENT_ID"` → Яндекс отвечает 400 invalid_client.
- Google "ругается на токен" — `UNREGISTERED_ON_API_CONSOLE`: приложение не зарегистрировано
  в Google Cloud Console. Плюс критический баг: `UserRecoverableAuthException` (диалог
  согласия) тонул в `runCatching`, поэтому первый вход ВСЕГДА заканчивался ошибкой.

**Решение:**
- Создан `data/auth/OAuthConfig.kt` — единое место для client_id + признаки
  `isYandexConfigured` / `isGoogleConfigured`.
- `GoogleAuthDataSource.getAccessToken()` возвращает sealed `GoogleTokenResult`
  (Success / **ConsentRequired(intent)** / Failure) + `diagnose()` с человекочитаемыми
  причинами (UNREGISTERED_ON_API_CONSOLE, INVALID_AUDIENCE, ACCOUNT_MISSING...).
- `AuthRepository.signInWithGoogle()` → `GoogleSignInResult` (Success/ConsentRequired/Failure).
- `AuthScreen` / `SettingsScreen` — launcher для диалога согласия, повторный вход после RESULT_OK.
- `YandexAuthDataSource` — валидация client_id до открытия браузера, `state` для защиты
  редиректа, парсинг фрагмента через `substringAfter` (не ломается на '=' внутри токена).
- `AuthScreen` — диалог «Настройка входа» с пошаговой инструкцией, пока OAuth не настроен.

**Ключевые значения этого проекта (для настройки OAuth):**
- Package: `com.example.mycalendar`
- SHA-1 (debug): `76:13:F0:79:E8:CA:6F:4C:65:06:B7:AB:48:A4:65:BC:61:46:BD:74`
- Yandex redirect URI: `mycalendar://oauth`
- На эмуляторе есть Google-аккаунт `obogrey@gmail.com` и Play Services.

**ВАЖНО:** рабочий вход требует регистрации OAuth-клиентов пользователем —
Google Cloud Console (Android client: package + SHA-1 + Calendar API включён)
и oauth.yandex.ru (client_id в `OAuthConfig.YANDEX_CLIENT_ID`).
Без этого физически невозможно (требование OAuth 2.0); приложение при этом
корректно работает в гостевом режиме с понятными сообщениями об ошибках.

## Системный календарь: синхронизация БЕЗ OAuth + тест в эмуляторе Android 9

**Архитектурное решение (реализовано в прошлой сессии, верифицировано сейчас):**
- Google синхронизируется через `CalendarContract` (системный календарь), без регистрации
  в Google Cloud Console. `SystemCalendarDataSource` пишет/читает события реального
  CalendarProvider эмулятора (аккаунт `obogrey@gmail.com`).
- Яндекс-карточка скрыта, пока `OAuthConfig.isYandexConfigured == false`.
- `hasReliableUpdatedAt = false` → pull читает ВСЕ события, конфликты по СОДЕРЖИМОМУ
  (`sameContent`), удаления по флагу `DELETED=1`.
- Заметки (textNote / voiceNotePath) НЕ пишутся в CalendarContract по дизайну — они
  ЛОКАЛЬНЫЕ. `RemoteEvent` не имеет полей заметок, поэтому `RemoteEvent.toEvent()`
  возвращает событие с `textNote=null, voiceNotePath=null`.

**Добавлен тест `event_withVoiceAndTextNote_roundTrip` в `SystemCalendarTest.kt`:**
событие с ОБОИМИ заметками одновременно (textNote + voiceNotePath) проходит
insert → fetch → update → delete на реальном CalendarProvider без ошибок; ядро
(название/время/напоминания/повтор MONTHLY) корректно round-trip; подтверждается,
что pull возвращает заметки пустыми (они не уходят в облако).

**Команды запуска на эмуляторе Android 9 (API 28, AVD `Medium_Phone`):**
```
adb=$LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest
$adb install -r -t app/build/outputs/apk/debug/app-debug.apk
$adb install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
$adb shell pm grant com.example.mycalendar android.permission.READ_CALENDAR
$adb shell pm grant com.example.mycalendar android.permission.WRITE_CALENDAR
$adb shell am instrument -w -r com.example.mycalendar.test/com.example.mycalendar.HiltTestRunner
```
**Результат (07.09 / Android 9, эмулятор-5554): `OK (11 tests)`** —
включая `event_withVoiceAndTextNote_roundTrip` и `insert_update_delete_roundTrip`.
Тестовый раннер: `com.example.mycalendar.HiltTestRunner` (НЕ стандартный AndroidJUnitRunner).
